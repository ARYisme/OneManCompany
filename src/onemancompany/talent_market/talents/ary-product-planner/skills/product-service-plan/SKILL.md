# 產品與服務企劃 SOP（精簡版 PRD）

## 開始前確認（不清楚就問，最多 3 題，給 A/B/C 選項）
1. 是 UZENA 還是 GWIs？產品還是服務？
2. 想解決誰的什麼問題？成功長什麼樣子（數字）？
3. 預算、上線期限、不能做的事？

## 步驟
1. 讀自家官網，寫 3 行「我們是誰、賣什麼、賣給誰」。
2. 改寫老闆原始需求（一段話），讓老闆確認理解正確。
3. 產品目標：最多 3 個，彼此不重疊，每個有可量化指標。
4. 目標客群與使用者故事：3–5 則，格式「身為〔誰〕，我想要〔什麼〕，這樣我就能〔好處〕」，每則附驗收條件。
5. 競品／替代方案：需要時請市場研究員（00006）提供 5–7 家比較，或用 web_search／web_fetch 自查並附來源。
6. 需求清單與優先順序：P0（必做）／P1（應做）／P2（可做），或 MoSCoW（Must／Should／Could／Won't）。
   需要排序很多項時用 RICE：分數 =（觸及人數 × 影響 0.25–3 × 信心 %）÷ 工作量（人月），寫出每個值的依據。
7. 風險與待決事項：列出不確定的地方，交給老闆決定。

## 交件格式
```
## 結論（3 句：建議做什麼、為什麼、下一步）
## 背景與原始需求
## 產品目標（≤3，含指標）
## 目標客群與使用者故事（3–5，含驗收條件）
## 競品／替代方案比較表（含來源）
## 需求清單（優先順序與理由）
## 風險與待老闆決定
## 來源（含查詢日期）
```

## 品質檢查清單
- [ ] 第一段就是結論
- [ ] 目標 ≤3 個且可量化
- [ ] 每則使用者故事有驗收條件
- [ ] 優先順序有方法與理由
- [ ] 數字都有來源＋日期，或標「假設」
- [ ] 沒有編造；查不到寫「查不到」

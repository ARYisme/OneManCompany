# 程式審查 SOP

## 步驟
1. 先看 README 和授權（LICENSE），記下授權種類（MIT、Apache-2.0、GPL…）。
2. 看整體結構：進入點在哪、主要模組有哪些。
3. 逐項檢查：
   - 安全：有沒有寫死的金鑰、不安全的指令拼接、任意執行程式碼。
   - 正確：邊界情況、錯誤處理、併發問題。
   - 維護：命名、重複程式、測試有沒有。
4. 每個問題標嚴重度：🔴 必修／🟡 建議／🟢 小事，附「檔案:行號」。

## 交件格式
```
## 結論（能不能用／能不能合併）
## 問題清單（嚴重度｜位置｜說明｜建議改法）
## 授權注意事項
```

## 品質檢查清單（v2，交件前逐項確認）
- [ ] 有「怎麼測」與實際測試結果
- [ ] 有「怎麼還原」
- [ ] 沒有密碼、金鑰、token 進入檔案或回報
- [ ] 沒碰正式環境，或已取得老闆同意
- [ ] 做不到的地方已明講，沒有謊報完成

## 做不到時
- 缺工具、權限或資料：直說做不到與原因，列出已完成與未完成的部分；不准謊報完成，不准寫程式繞過。

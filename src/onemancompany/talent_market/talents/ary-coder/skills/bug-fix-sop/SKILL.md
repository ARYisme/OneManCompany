# 修 Bug 的 SOP

## 開始前確認
1. 錯誤訊息或截圖是什麼？什麼時間發生？
2. 在哪個程式／服務？能不能重現？

## 步驟
1. 收集證據：找出完整錯誤訊息（traceback）和發生前後 20 行 log。
2. 定位：用 `grep`/`rg` 找出錯誤訊息在程式碼的哪一行，讀懂上下文。
3. 找原因：用一句話寫出「因為 A，所以 B 壞掉」。說不出來就繼續查，不要亂改。
4. 最小修正：只改必要的幾行，不順便重構。
5. 驗證：寫一個能重現問題的小測試或指令，修前失敗、修後通過。
6. 自我檢查：
   - [ ] 有沒有影響其他功能？
   - [ ] 有沒有把金鑰寫進檔案？
   - [ ] 有沒有說明怎麼還原？

## 交件格式
```
## 結論（原因一句話＋修好了沒）
## 證據（錯誤訊息、檔案:行號）
## 改了什麼（檔案清單＋diff 重點）
## 怎麼測／怎麼還原
```

## 品質檢查清單（v2，交件前逐項確認）
- [ ] 有「怎麼測」與實際測試結果
- [ ] 有「怎麼還原」
- [ ] 沒有密碼、金鑰、token 進入檔案或回報
- [ ] 沒碰正式環境，或已取得老闆同意
- [ ] 做不到的地方已明講，沒有謊報完成

## 做不到時
- 缺工具、權限或資料：直說做不到與原因，列出已完成與未完成的部分；不准謊報完成，不准寫程式繞過。

# 安全變更 SOP

## 開始前確認
1. 要改什麼？影響哪個服務、哪些人？老闆是否明確同意這個改動？
2. 有沒有停機？可以接受的時段？

## 步驟
1. 先備份：寫出備份檔路徑（不要把機密內容印出來）。
2. 寫變更計畫：改哪些檔案、預期結果、怎麼驗證、怎麼還原。
3. 小步做：一次只改一件事，每步驗證。
4. 驗證：貼出實際指令輸出或測試結果（遮掉任何機密）。
5. 失敗就照還原步驟還原，並回報原因；不要換一種繞路的方法硬做。
6. bash 會以 nobody 身分執行，Gmail API、OAuth、/run/secrets、token 檔一律被擋；被擋就停下來回報。

## 交件格式
```
## 結論（成功／失敗／部分完成）
## 改了什麼（檔案、行）
## 備份位置
## 驗證結果（實際輸出）
## 還原步驟
## 沒做到的事與原因
```

## 品質檢查清單
- [ ] 有老闆同意
- [ ] 有備份，且有還原步驟
- [ ] 驗證結果是實際輸出，不是推測
- [ ] 沒有印出或寫入任何機密
- [ ] 沒有用程式繞過工具限制

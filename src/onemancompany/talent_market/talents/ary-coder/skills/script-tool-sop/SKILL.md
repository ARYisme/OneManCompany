# 寫小工具／腳本的 SOP

## 開始前確認
1. 輸入是什麼（檔案、網址、API）？輸出要什麼格式（CSV、JSON、Markdown）？
2. 多久跑一次？要不要排程？
3. 需要金鑰嗎？（需要的話請老闆用環境變數提供，不要貼在對話裡）

## 步驟
1. 先用 5～10 行做出最小可用版本，用真實小資料跑一次。
2. 加上錯誤處理：網路失敗要重試 2 次、資料缺欄位要清楚報錯。
3. 在檔案開頭寫用法說明（怎麼執行、參數、範例）。
4. 用 `python -m py_compile` 或實際執行確認沒有語法錯誤。
5. 把執行結果的前幾行貼在回報裡當證明。

## 交件格式
```
## 做好了什麼（一句話）
## 檔案位置與用法
## 實際執行結果（節錄）
## 已知限制
```

## 品質檢查清單（v2，交件前逐項確認）
- [ ] 有「怎麼測」與實際測試結果
- [ ] 有「怎麼還原」
- [ ] 沒有密碼、金鑰、token 進入檔案或回報
- [ ] 沒碰正式環境，或已取得老闆同意
- [ ] 做不到的地方已明講，沒有謊報完成

## 做不到時
- 缺工具、權限或資料：直說做不到與原因，列出已完成與未完成的部分；不准謊報完成，不准寫程式繞過。
